# LeakSanitizer suppressions for the C++ SDK test suite.
#
# These cover allocations the Rust FFI core intentionally keeps for the whole
# process lifetime — they are reachable, not lost, so flagging them as leaks is
# a false positive. `RUNTIME` and `HEADER_KEY_CACHE` are `once_cell::sync::Lazy`
# globals in rust/ffi/src/common.rs that are never dropped; the tokio runtime
# they hold spins up worker threads whose allocations stay live until exit.
#
# The patterns are scoped to the lazy-init and tokio-runtime construction paths
# rather than all of `once_cell`/`tokio`. Caveat: LSan matches a suppression
# against any frame in the leak's stack, so a genuine leak whose stack passes
# through `tokio::runtime` (e.g. inside a spawned `_nowait` task) could still be
# masked. Wrapper-owned leaks (a missed zerobus_free_error_message, a leaked
# CHeader array, a leaked proto-bytes buffer) do not route through these frames
# and remain detectable. Keep the patterns as tight as the runtime allows.
leak:once_cell::sync::Lazy
leak:tokio::runtime
